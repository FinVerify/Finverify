## 2. Motivation and Purpose

FinVerifyBench operationalizes the central finding of the FinVerify paper: that numerical hallucination errors in task-specifically fine-tuned financial LLMs are **statistically structured** rather than random (χ²=41.97, p<0.001). The benchmark enables:

- **Measuring** structured error rates across model families
- **Evaluating** deterministic correction methods (DVL and successors)
- **Benchmarking** CoT, RAG, and tool-use interventions on structured error classes
- **Tracking** progress toward numerically reliable financial AI

## 4. Data Collection and Curation

### 4.1 Generation Method

All samples are synthetically generated by a deterministic Python generator (`scripts/create_dataset.py`). Each sample is created by a typed factory function that:

1. Takes raw financial parameters (revenues, costs, asset values, etc.)
2. Computes the mathematically correct `ground_truth` using Python floating-point arithmetic
3. Formats a realistic financial statement `context` with correct unit headers
4. Assigns error taxonomy labels based on the template family

No proprietary financial data is included. All values are fictional but realistic in magnitude and structure.

### 4.2 Verification Protocol

- Every `ground_truth` is derived programmatically from its context parameters
- `scripts/verify_calculations.py` re-derives answers from context numbers and flags discrepancies
- `scripts/validate_dataset.py` checks schema, enum membership, and semantic consistency
- 100% of samples pass both automated validation passes (0 failures at release)

> **Human review status:** The automated checks above have been executed and pass at 100%. The human-review and inter-annotator agreement process described in `BENCHMARK_DESIGN.md` §7–8 has **not yet been executed** on the current 500-sample release. See `BENCHMARK_DESIGN.md` §8 for planned process details.

## 5. Evaluation Protocol

### 5.1 Primary Metric

**Execution Accuracy** with 5% relative tolerance:

```
correct(ŷ, y) = 1 if |ŷ - y| / |y| ≤ 0.05 else 0
```

Matches the original FinQA evaluation protocol (Chen et al., 2021).

### 5.2 Secondary Metrics

- Mean Relative Error (MRE)
- Underestimation Rate (wrong predictions where ŷ < y)
- Per-category Accuracy
- Per-difficulty Accuracy
- Calibration statistics

### 5.3 Statistical Tests

- McNemar's test for pairwise model comparisons
- Bootstrap resampling (1,000 iterations) for confidence intervals
- Binomial test for directional bias (underestimation/overestimation)

## 7. Limitations

1. **Synthetic origin** — all samples are generated, not extracted from real SEC filings. Real filings contain additional noise (OCR artifacts, table formatting inconsistencies) not present here.
2. **English only** — no multilingual financial documents in v1.0.
3. **Finance domain only** — v1.0 covers only financial numerical reasoning. Cross-domain expansion is planned.
4. **Small model focus** — motivated by 7–8B model findings; behavior at 70B+ scale is an open question.
5. **No conversational QA** — samples are single-turn; ConvFinQA-style error propagation is not covered.
6. **No program synthesis** — samples require numerical output, not executable programs.

---

## 8. Intended Uses

**Appropriate uses:**
- Evaluating numerical reliability of financial LLMs
- Developing and testing correction methods (DVL variants)
- Benchmarking prompt engineering strategies on financial numerical tasks
- Research into structured vs. random error distributions in LLMs

**Inappropriate uses:**
- Evaluating general financial knowledge or sentiment
- Using synthetic examples as substitutes for real regulatory document analysis
- Claiming SOTA on financial NLP without comparison to FinQA, TAT-QA baselines

---

## 9. Ethical Considerations

- No real personal or company financial data is used
- All ground-truths are verifiable mathematical facts
- Benchmark does not encode any investment advice
- Errors in AI systems on this benchmark do not reflect errors in actual financial reporting
